## 二、发现的极端场景与修复方案

### 2.1 安全类（最严重）

#### ⚠️ 漏洞 1：危险命令黑名单可被"空白绕过"

**攻击方式**：

```python
registry.call("run_command", {"cmd": "rm  -rf /"}, ADMIN)
#                                     ↑ 双空格
# 旧版: cmd.lower().strip() 后 "rm  -rf" 不匹配黑名单里的 "rm -rf" → 放行！
```

**修复**（`default_tools.py`）：先做**空白归一化**再匹配：

```python
cmd_lower = " ".join(cmd.lower().split())   # 任意空白压缩成单个空格
```

`"rm  -rf /"` → 归一化后 `"rm -rf /"` → 命中黑名单 ✅

#### ⚠️ 漏洞 2：黑名单关键词覆盖不全

新增拦截：`rm -fr`（换序参数）、`:(){`（fork 炸弹）、`mv /*`、
`find / -delete`、`chmod -r 777`。

#### ⚠️ 漏洞 3：只有 delete_file 检查受保护路径

**攻击方式**：

```python
registry.call("write_file", {"path": "/etc/passwd", "content": "hacker:x:0:0:..."})
registry.call("read_file",  {"path": "/etc/shadow"})   # read_file 是 PUBLIC 级！
```

删除有防护，但**写/读/复制/移动全部裸奔**。

**修复**：新增 `_is_protected_path()` 的全入口覆盖——
`write_file` / `read_file` / `copy_file`(目标) / `move_file`(目标) 全部拒绝
系统目录；同时把 `PROTECTED_PATHS` 扩展到 Windows（`C:\Windows` 等），
并改为**大小写不敏感 + 原始路径/解析路径双重比对**。

#### ⚠️ 漏洞 4：受保护路径在 Windows 上失效

旧版 `Path(path).resolve()` 在 Windows 把 `/etc/passwd` 解析成
`C:\etc\passwd`，与 `"/etc"` 前缀永远匹配不上。修复后双平台一致生效。

### 2.2 资源类

#### ⚠️ 漏洞 5：read_file 无大小限制

一个 10GB 的日志文件会被整个 `f.read()` 进内存 → 进程 OOM。

**修复**：`MAX_READ_SIZE = 10MB`，超限直接返回
`"文件过大 (10240MB)，超过读取上限 10MB"`。

#### ⚠️ 漏洞 6：find_duplicate_files 整文件读入内存算 MD5

**修复**：改为 1MB 分块流式哈希（`iter(lambda: f.read(1MB), b"")`），
1GB 文件内存占用从 1GB 降到 1MB。配套测试验证了分块哈希结果与整块一致。

### 2.3 健壮性类

#### ⚠️ 漏洞 7：重复注册 MCP Mock 工具直接崩溃

`register_mock_tools()` 调用两次 → `ValueError: 工具 'mcp_search' 已注册`。
**修复**：注册前先 `registry.has()` 判断，改为**幂等操作**。

#### ⚠️ 漏洞 8：技能重名处理会用 `_dup` 互相覆盖

目录里已有 `文档/a.pdf` 和 `文档/a_dup1.pdf` 时，再整理一个 `a.pdf`
会把 `a_dup1.pdf` **覆盖丢失**。**修复**：`_dup1 / _dup2 / _dup3 ...`
递增命名，永不覆盖。配套测试验证三重碰撞下所有文件完好。

#### ⚠️ 漏洞 9：统计模块崩溃会拖垮工具调用

如果 `stats.record()` 抛异常（磁盘满 / JSON 序列化失败），整个 `call()`
会跟着失败。**修复**：抽出 `_record_stats()`，统计失败静默忽略——
**统计是旁观者，不是参与者**。

### 2.4 顺手补全：schema 参数校验

ToolSchema 定义了每个工具的必需参数，但 `call()` 从来没校验过。
现在调用前预检：缺必需参数 → `"参数错误: 缺少必需参数: src, dest"`，
`params` 不是字典 → 同样拦截。校验失败也会计入统计（被拒绝的调用也要留痕）。

## 六、遗留说明（面向未来）

1. **黑名单 vs 白名单**：`run_command` 目前用黑名单，理论上仍可构造出
   绕过变体（如 base64 编码后管道执行）。教学项目保持黑名单的"可讲解性"，
   生产环境应换成白名单或去掉 `shell=True`。
2. **真实 MCP 接入**：`connect_real_mcp()` 仍是预留接口，替换 Mock 只需
   `pip install mcp` 并实现 stdio 连接，接口签名已冻结，组 3 无需改动。
3. **并发安全**：当前设计为单线程 Agent 调用；多线程场景下 stats 的
   `_counters` 需要加锁（在 report 中已注明）。
