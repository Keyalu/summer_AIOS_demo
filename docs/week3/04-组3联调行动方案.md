## 一、联调前：我们该做什么（本周可完成）

### 1. 发给组 3 的材料清单

| 材料 | 作用 | 位置 |
|------|------|------|
| `linux-agentic-os-group4.zip` | 完整可运行包 | 项目根目录 |
| 《02-组间集成指南.md》 | **必读**：接口契约 + 错误分类速查 + 5 分钟验收清单 | zip 内 docs/week3/ |
| `tests/test_integration.py` | 组 3 接入方式的 7 种参考写法（SimulatedAgent 就是他们的最小近似） | zip 内 tests/ |

### 2. 约联调时要对齐的 4 个问题

1. **组 3 怎么实例化？** 推荐 `ToolRegistry(stats=ToolStats())` + `SkillLibrary(registry)`（共享统计）
2. **权限策略？** 建议平时 USER、用户确认后临时提权 ADMIN（指南第 3 节）
3. **要不要 MCP Mock 工具？** 要就 `MCPConnector().register_mock_tools(registry)`（幂等）
4. **组 3 的单元测试环境？** 不想碰真实文件系统就用 `MockToolRegistry`（接口 100% 一致）

### 3. 环境约定

- Python 3.10+，纯标准库，**零依赖冲突风险**（这是我们模块的最大对接优势）
- 两边先各自跑通：`python main.py` + `python -m pytest tests/ -v`

## 二、联调当天：三阶段递进（每阶段有通过标准）

### 阶段 1：契约自查（15 分钟）—— 各自独立就能做

组 3 在他们环境里跑我们的验收清单：

```bash
python main.py                                  # 8 步演示全绿
python quick_check.py                           # 快速验证 PASS
python -m pytest tests/ docs/week3/test_week3.py -q   # 应全过
```

**通过标准**：全绿。任何一项失败 → 先查环境（Python 版本、工作目录），再联系分组四。

### 阶段 2：Mock 换真实（30 分钟）—— 核心一步

组 3 把自己的 Agent 代码里的：

```python
registry = MockToolRegistry()      # 并行开发期间用的
skills = MockSkillLibrary()
```

改成：

```python
registry = ToolRegistry()
skills = SkillLibrary(registry)
```

**通过标准**：组 3 的 Agent 流程原样跑通，无需修改任何其他代码。
如果这里需要改他们的调用代码 → 说明契约被破坏，**这是分组四的 bug，立即记录**。

### 阶段 3：端到端场景（60 分钟）—— 真实任务演练

用 `tests/test_integration.py` 里的 7 个场景做剧本，两边一起过：

| # | 场景 | 验证点 |
|---|------|--------|
| 1 | "整理我的下载文件夹" | Agent 决策 → organize_downloads → 文件真的分类了 |
| 2 | 权限提权流 | USER 被拒 → 用户确认 → ADMIN 放行 |
| 3 | 安全底线 | 提权后 `rm -rf /` 依然被拒（组 3 不许绕过） |
| 4 | 错误自愈 | 工具名写错 → error 前缀 → list_tools 纠正 |
| 5 | Schema 内省 | list_tools().to_dict() 直接喂 LLM function-calling |
| 6 | 统计汇报 | 任务结束读 success_rate 向用户汇报 |
| 7 | MCP 通道 | JSON-RPC 往返 + -32601 错误码 |

**通过标准**：7 个场景全部按预期表现。可先把我们的 `test_integration.py`
跑一遍预热——**它全过，说明契约侧没有障碍，剩下的问题都在组 3 的 Agent 逻辑里**。
