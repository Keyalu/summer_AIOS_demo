## 1. 一分钟接入

```python
from src import ToolRegistry, ToolStats, PermissionLevel

stats = ToolStats(log_path="agent_stats.json")   # 统计可选
registry = ToolRegistry(stats=stats)

# 调用任何一个工具，拿到的永远是同一种结构
r = registry.call("list_directory", {"path": "/home/user"}, PermissionLevel.PUBLIC)
print(r.to_dict())
# {'success': True, 'result': {'path': ..., 'count': 8, 'entries': [...]}}
```

开箱即有 **8 个 OS 工具 + 8 个 OS 技能 + 3 个 MCP Mock 工具**，
纯标准库实现，无任何第三方依赖。

## 2. 统一返回格式（ToolResult）

组 3 只需要处理这一种结构：

```python
r.success                 # bool  —— 先判断这个
r.result                  # 任何类型，成功时有值
r.error                   # str，失败时有值
r.to_dict()               # {"success": True, "result": ...}
                          # {"success": False, "error": ...}
```

**错误分类速查**（读 `r.error` 的前缀即可）：

| error 前缀 | 含义 | 组 3 应该怎么做 |
|-----------|------|----------------|
| `工具未注册:` | 工具名写错了 | 检查 `list_tools()` 返回的名字 |
| `权限不足:` | 权限级别不够 | 提升调用时的 user_level，或改用低权限工具 |
| `参数错误:` | 缺参 / 类型不对 | 按 schema 修正参数 |
| `拒绝执行:` | 命中危险命令黑名单 | 不要重试同一命令 |
| `受保护` | 目标在系统目录 | 换用户空间路径 |
| `执行异常:` | 工具内部出错 | 记录日志，可重试 |

---

## 3. 权限模型（三级）

```python
PermissionLevel.PUBLIC   # 只读：list_directory / read_file
PermissionLevel.USER     # 文件操作：copy/move/delete/create/write
PermissionLevel.ADMIN    # 执行命令：run_command
```

调用时传入的 `user_level.rank()` ≥ 工具要求的 rank 才放行。
**建议**：AppAgent 平时用 USER 运行，仅在有用户确认时临时提权到 ADMIN。

## 4. 调用 OS 技能（多工具编排）

```python
from src import SkillLibrary

skills = SkillLibrary(registry=registry)     # 传入 registry 即可共享统计
r = skills.call_skill("organize_downloads", {"path": "~/Downloads"})
```

可用技能：`organize_downloads` / `system_check` / `find_files` /
`cleanup_temp` / `backup_directory` / `find_large_files` /
`find_duplicate_files` / `disk_usage`。

注意：Skill 直接操作文件系统，**不经过 Registry 权限检查**（设计如此，
权限控制发生在工具层），Week 3 已在技能内部加入系统目录保护。

## 5. MCP 工具与 JSON-RPC

```python
from src import MCPConnector

mcp = MCPConnector()
mcp.register_mock_tools(registry)     # 幂等，可安全重复调用

# 方式一：普通调用
r = registry.call("mcp_search", {"query": "UFO 框架"})

# 方式二：JSON-RPC 2.0 格式
resp = mcp.mock_jsonrpc_call(registry, "mcp_weather", {"city": "上海"})
# 成功: {"jsonrpc": "2.0", "result": "...", "error": None, "id": 12345}
# 失败: error.code == -32601 → 方法不存在；-32603 → 执行失败
```

## 6. 并行开发：Mock 实现（接口 100% 一致）

组 3 的单元测试如果不想真的碰文件系统，用 Mock 替换即可，
**一行都不用改调用代码**：

```python
from src import MockToolRegistry, MockSkillLibrary   # 与真实实现同接口

registry = MockToolRegistry()          # 返回带 [Mock] 标记的假结果
skills = MockSkillLibrary()
```

| 真实 | Mock | 行为差异 |
|------|------|---------|
| `ToolRegistry` | `MockToolRegistry` | 不执行 OS 操作，返回 `[Mock] xxx` |
| `SkillLibrary` | `MockSkillLibrary` | 同上，`result.status` 带标记 |
