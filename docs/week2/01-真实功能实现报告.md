## 3. ToolRegistry 真实实现详解

### 3.1 核心职责

ToolRegistry 是整个系统的**工具调度中心**。它不直接操作文件系统——而是把"做什么"（工具名称）和"怎么做"（具体函数）解耦。AppAgent 只需要知道工具名和参数，不需要关心底层实现。

### 3.2 八个默认工具

| # | 工具名 | 权限 | 底层实现 | 功能描述 |
|---|--------|------|---------|---------|
| 1 | `copy_file` | user | `shutil.copy2()` | 复制文件，保留元数据（修改时间等） |
| 2 | `move_file` | user | `shutil.move()` | 移动/重命名文件，跨文件系统自动 fallback |
| 3 | `delete_file` | user | `shutil.rmtree()` / `.unlink()` | 删除文件或目录树 |
| 4 | `create_folder` | user | `Path.mkdir(parents=True)` | 递归创建目录（不存在则创建父目录） |
| 5 | `list_directory` | **public** | `Path.iterdir()` + `stat()` | 列出目录内容（名/类型/大小/后缀） |
| 6 | `read_file` | **public** | `open(...,"r",encoding="utf-8")` | 读文本文件，二进制文件返回错误提示 |
| 7 | `write_file` | user | `open(...,"w",encoding="utf-8")` | 写文本文件，自动创建父目录 |
| 8 | `run_command` | **admin** | `subprocess.run(shell=True)` | 执行 shell 命令，有超时和安全过滤 |

### 3.3 关键设计决策

#### 决策 1：统一返回格式

所有工具函数的返回值都是 `dict`，格式为：

```python
# 成功时
{"success": True, "result": "已复制: a.txt → b.txt"}

# 失败时
{"success": False, "error": "源文件不存在: /a.txt"}
```

**为什么这样设计？**
- 任务书明确要求 `tool_result_json = {"success": ..., "result": ...}`
- ToolRegistry.call() 内部会检测这个 dict 并包装成 `ToolResult` 对象
- 组3拿到的是统一的 `ToolResult`，用 `if result.success` 即可判断

#### 决策 2：权限三级模型

```python
class PermissionLevel(str, Enum):
    PUBLIC = "public"    # rank=0: 所有人可调
    USER   = "user"      # rank=1: 认证用户
    ADMIN  = "admin"     # rank=2: 仅管理员
```

**映射到工具：**

| 权限级别 | 工具 | 设计理由 |
|----------|------|---------|
| **PUBLIC** | list_directory, read_file | 只读操作不会改变系统状态，任何人都可以查看 |
| **USER** | copy_file, move_file, delete_file, create_folder, write_file | 改变文件系统状态，需要认证身份 |
| **ADMIN** | run_command | 可以执行任意命令，是最高危操作，仅限管理员 |

**验证方式：** `call(name, params, user_level)` 内部比较 `user_level.rank() >= schema.permission.rank()`

#### 决策 3：安全过滤层

```python
DANGEROUS_KEYWORDS = [
    "rm -rf", "rm -r", "rmdir", "mkfs", "dd ",
    "format", "shutdown", "reboot", ...
]

PROTECTED_PATHS = ["/etc", "/usr", "/root", "/boot", ...]
```

两层防护：
1. **命令关键词黑名单** — `run_command()` 在执行前检查命令字符串是否包含危险词
2. **受保护路径检查** — `delete_file()` 在删除前检查目标是否在系统关键路径下

这对应任务书安全评分项中提到的 **5 种危险命令**（rm/format/shutdown/dd 等）。

#### 决策 4：装饰器注册模式

除了显式调用 `register()`，还支持 Python 装饰器语法：

```python
registry = ToolRegistry()

@registry.tool("greet", description="打招呼")
def greet(name: str) -> dict:
    return {"success": True, "result": f"Hello, {name}!"}

# 使用
registry.call("greet", {"name": "World"})  # → ToolResult.ok("Hello, World!")
```

这让扩展新工具非常自然——定义函数 + 加装饰器即可，无需手动维护注册表。

#### 决策 5：调用统计集成

```python
stats = ToolStats()
registry = ToolRegistry(stats=stats)
registry.call("copy_file", ...)  # 自动记录到 stats
```

每次 `call()` 成功或失败都会生成一条 `CallRecord`，包含：
- 工具名、参数、成功/失败、耗时（毫秒）、错误信息

统计模块提供：
- `total_calls()` — 总调用次数
- `report()` — 每个工具的 `{calls, success, fail}` 汇总
- `success_rate()` — 全局或单工具成功率
- `avg_duration()` — 平均响应时间
- 持久化 JSON（原子写入防崩溃）

## 4. SkillLibrary 真实实现详解

### 4.1 核心概念：Skill vs Tool

| 维度 | Tool | Skill |
|------|------|-------|
| 粒度 | 单一原子操作 | 多步编排组合 |
| 举例 | copy_file, move_file | organize_downloads（扫描+分类+移动） |
| 复杂度 | ~10 行 | ~30-50 行 |
| 调用方 | 直接被 AppAgent 调用 | 被 AppAgent 或其他 Skill 调用 |
| 内部逻辑 | 一个 shutil/subprocess 调用 | 多次 Tool 调用的编排 |

**Skill 的本质是把常用的"多步操作流程"封装成一步调用。** 组3 不需要知道 organize_downloads 内部做了什么，只需要调一个 `call_skill("organize_downloads")`。

### 4.2 八个默认 Skill

| # | 技能名 | 核心算法 | 输入 | 输出 |
|---|--------|---------|------|------|
| 1 | **organize_downloads** | 遍历目录 → 按扩展名分类 → 移动到子文件夹 | path（可选） | total_moved, categories 映射表 |
| 2 | **system_check** | `shutil.disk_usage` + `/proc/meminfo` + 进程计数 | 无 | disk/memory/process_count/hostname |
| 3 | **find_files** | `Path.rglob(pattern)` 递归搜索 | directory, pattern | 匹配文件列表(≤100条) |
| 4 | **cleanup_temp** | 遍历目录 → 检查 mtime → 删除过期文件 | path, max_age_days | removed_count, errors |
| 5 | **backup_directory** | `shutil.make_archive("zip")` | src, dest(可选) | 备份 zip 路径 |
| 6 | **find_large_files** | `rglob(*)` → `stat().st_size` → 过滤排序 | path, min_size_mb, top_n | 大文件列表(按大小降序) |
| 7 | **find_duplicate_files** | `rglob(*)` → 逐文件 MD5 哈希 → 分组 | path | 重复组列表(同MD5的文件集) |
| 8 | **disk_usage** | `shutil.disk_usage(path)` | path | total/used/free/percent |

### 4.3 重点 Skill 实现细节

#### organize_downloads — 文件分类整理

这是 PPT 演示的核心功能。算法流程：

```
1. 接收 path 参数，expanduser() 解析 ~/ 为实际路径
2. Path.is_dir() 验证目录存在
3. 遍历目录下每个文件：
   a. 跳过隐藏文件（以 . 开头）
   b. 取文件扩展名 .suffix.lower() → ".pdf"
   c. _classify(".pdf") → 在 FILE_CATEGORIES 中查找 → "文档"
   d. 创建子目录: base/"文档"/ (exist_ok=True 避免报错)
   e. 如果目标已存在同名文件 → 加 _dup 后缀避免覆盖
   f. shutil.move(source, destination) 执行移动
4. 返回汇总: {total_moved: N, categories: {"文档":["a.pdf"],...}, skipped:[".gitignore"]}
```

文件分类规则（FILE_CATEGORIES）覆盖 7 大类、40+ 扩展名：

| 分类 | 包含扩展名 |
|------|-----------|
| 文档 | pdf/doc/xls/ppt/txt/md/csv... |
| 图片 | jpg/png/gif/bmp/svg/webp... |
| 视频 | mp4/avi/mkv/mov/wmv... |
| 音频 | mp3/wav/flac/aac/ogg... |
| 压缩包 | zip/rar/7z/tar/gz... |
| 代码 | py/js/java/c/go/rb/sh/json/yaml... |
| 安装包 | exe/msi/deb/rpm/dmg/apk... |

未匹配的扩展名归入 **"其他"** 目录。

#### find_duplicate_files — 重复文件查重

算法原理：

```
对每个文件 f:
  1. 以二进制模式 open(f, "rb")
  2. 读取全部内容 f.read()
  3. 计算 MD5 哈希 hashlib.md5(content).hexdigest()
  4. 存入 hashes 字典: {"abc123": [file_a, file_b], "def456": [file_c]}

过滤结果:
  duplicates = {h: paths for h, paths in hashes.items() if len(paths) > 1}
```

**时间复杂度：** O(N × F)，N 是文件数，F 是平均文件大小（读取整个内容做哈希）。对于小目录（< 1000 文件）完全够用；大规模场景可以优化为先比较文件大小再比较哈希。

**空间复杂度：** O(N) 存储哈希字典。

#### backup_directory — 压缩备份

使用 Python 标准 `shutil.make_archive()`：

```python
shutil.make_archive(dest, "zip", root_dir=str(src_p))
# 生成: dest.zip（递归打包 src_p 下所有文件）
```

如果没指定 dest，自动用时间戳命名：`{src}_{20260713_091000}_backup.zip`

## 6. 安全机制总结

### 6.1 三道防线

```
AppAgent 发起调用
    │
    ▼
╔══════════════════════════╗
║  第一道：权限等级检查      ║  PermissionLevel 比较
║  public < user < admin    ║  run_command 需要 admin
╚═════════╤════════════════╝
            │ 通过
            ▼
╔══════════════════════════╗
║  第二道：危险命令黑名单     ║  DANGEROUS_KEYWORDS
║  rm -rf / format / dd .. ║  run_command 内部检查
╚═════════╤════════════════╝
            │ 通过
            ▼
╔══════════════════════════╗
║  第三道：受保护路径检查     ║  PROTECTED_PATHS
║  /etc /usr /root /boot   ║  delete_file 内部检查
╚═════════╤════════════════╝
            │ 通过
            ▼
      执行实际操作
```

### 6.2 各防线覆盖的工具

| 防线 | 生效于 | 不生效于 |
|------|--------|---------|
| **权限检查** | 所有 8 个工具 | — |
| **命令黑名单** | 仅 run_command | 其他 7 个工具（它们不用 subprocess）|
| **路径保护** | 仅 delete_file | copy/move/write/create/list/read（这些允许操作任意路径）|
