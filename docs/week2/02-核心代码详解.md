## 1. interfaces.py — 系统的"宪法"

### 1.1 为什么这个文件最重要

`interfaces.py` 定义了整个分组四模块的**类型系统**。所有其他文件都依赖它——ToolRegistry 实现了它定义的接口，SkillLibrary 也一样。如果改了这个文件，整个项目都会跟着变。

### 1.2 类型层次结构

```
基础枚举
├── ToolParamType     (string/number/boolean/object/array)
└── PermissionLevel   (public=0 / user=1 / admin=2)

数据容器 (dataclass)
├── ToolParam         (name, type, description, required, default)
├── ToolSchema        (name, description, parameters[], permission)
├── ToolResult        (success, result, error)       ← 最核心！
└── CallRecord        (tool_name, params, success, duration_ms, error)

函数签名
└── ToolFunc           = Callable[..., dict[str, Any]]

抽象接口 (ABC)
├── IToolRegistry     (register/call/list_tools/has/unregister)
├── ISkillLibrary     (register_skill/call_skill/list_skills)
└── IToolStats        (record/report/total_calls)
```

### 1.3 关键代码解读

#### ToolResult — 整个系统的数据协议

```python
@dataclass
class ToolResult:
    success: bool              # 唯一判断依据：if result.success
    result: Any = None         # 成功时的返回值（任意类型）
    error: str | None = None   # 失败时的描述

    def to_dict(self) -> dict:
        """转为任务书要求的 tool_result_json 格式"""
        if self.success:
            return {"success": True, "result": self.result}
        return {"success": False, "error": self.error}

    @staticmethod
    def ok(result=None) -> "ToolResult":
        return ToolResult(success=True, result=result)

    @staticmethod
    def fail(error: str) -> "ToolResult":
        return ToolResult(success=False, error=error)
```

**设计要点：**

1. **双字段分离** — 成功走 `result`，失败走 `error`，永远不会歧义。不像有些 API 用一个字段存所有东西然后靠解析判断。

2. **工厂方法** — `ToolResult.ok()` 和 `ToolResult.fail()` 让调用方不用记字段名：
   ```python
   return ToolResult.ok("复制完成")      # 比 ToolResult(True, "复制完成") 更语义化
   return ToolResult.fail("文件不存在")    # 比 ToolResult(False, None, "文件不存在") 更清晰
   ```

3. **to_dict()** — 直接对接任务书要求的 JSON 格式，组3拿到后直接 `json.dumps(result.to_dict())` 就能序列化。

#### PermissionLevel — 双重继承的巧妙之处

```python
class PermissionLevel(str, Enum):
    PUBLIC = "public"
    USER = "user"
    ADMIN = "admin"

    def rank(self) -> int:
        return {"public": 0, "user": 1, "admin": 2}[self.value]
```

**同时继承了 `str` 和 `Enum`：**
- 作为 `Enum` 可以做 `PermissionLevel.PUBLIC` 这样的引用
- 作为 `str` 可以直接比较字符串：`level == "public"` → `True`
- `rank()` 方法把权限等级数值化，方便大小比较

**为什么不用纯整数？** 因为 `"public"/"user"/"admin"` 在日志、错误信息、JSON 序列化中比 `0/1/2` 可读得多。

#### ToolSchema.to_dict() — MCP 协议适配

```python
def to_dict(self) -> dict:
    props = {}
    required = []
    for p in self.parameters:          # 遍历参数列表
        props[p.name] = {
            "type": p.type.value,      # "string", "number" 等
            "description": p.description,
        }
        if p.default is not None:
            props[p.name]["default"] = p.default  # 可选参数带默认值
        if p.required:
            required.append(p.name)               # 必填参数列表
    return {
        "name": self.name,
        "description": self.description,
        "permission": self.permission.value,
        "inputSchema": {                          # MCP 标准格式
            "type": "object",
            "properties": props,
            "required": required,
        },
    }
```

输出的字典可以直接喂给 MCP 的 `tools/list` 接口——LLM 拿到这个 schema 就知道该传什么参数、哪些是必填的。

## 2. tool_registry.py — 调度中枢

### 2.1 核心数据结构

```python
class ToolRegistry(IToolRegistry):
    def __init__(self, stats=None):
        self._tools: dict[str, ToolFunc] = {}       # 名字 → 函数
        self._schemas: dict[str, ToolSchema] = {}    # 名字 → 描述
        self._stats = stats                           # 统计模块（可选）
        self._register_defaults()
```

两个字典并行维护：
- `_tools[name] = func` — 存实际可调用的函数
- `_schemas[name] = schema` — 存工具的"说明书"

这样 **list_tools()** 只需要返回 `_schemas.values()`，不需要暴露内部函数。

### 2.2 call() 方法 —— 全文最关键的 60 行

```python
def call(self, name, params=None, user_level=PermissionLevel.USER) -> ToolResult:
    params = params or {}

    # ── 第 1 步：存在性检查 ──
    if name not in self._tools:
        return ToolResult.fail(f"工具未注册: {name}")

    # ── 第 2 步：权限检查 ──
    schema = self._schemas.get(name)
    required_perm = schema.permission if schema else PermissionLevel.USER
    if user_level.rank() < required_perm.rank():
        return ToolResult.fail(
            f"权限不足: '{name}' 需要 {required_perm.value}, "
            f"当前为 {user_level.value}"
        )

    # ── 第 3 步：计时 + 执行 + 异常处理 ──
    start = time.monotonic()
    try:
        raw = self._tools[name](**params)           # 解包字典为关键字参数
        duration = (time.monotonic() - start) * 1000

        if isinstance(raw, dict) and "success" in raw:
            result = ToolResult(**raw) if raw["success"] \
                else ToolResult.fail(raw.get("error", "未知错误"))
        else:
            result = ToolResult.ok(raw)             # 非 dict 返回值也包装

        if self._stats:                             # 统计记录
            self._stats.record(CallRecord(...))
        return result

    except TypeError as e:                          # 参数不匹配
        ...
    except Exception as e:                          # 其他异常
        ...
```

**逐行解析关键点：**

| 步骤 | 代码 | 作用 |
|------|------|------|
| 存在性 | `if name not in self._tools` | 防止调用不存在的工具导致 KeyError |
| 权限 | `user_level.rank() < required_perm.rank()` | 数值化比较：0<1<2 |
| 计时 | `time.monotonic()` | 不受系统时钟调整影响的高精度计时 |
| 调用 | `self._tools[name](**params)` | **解包操作**：`{"src":"/a","dest":"/b"}` → `func(src="/a", dest="/b")` |
| 返回值检测 | `isinstance(raw, dict) and "success" in raw` | 兼容两种风格：工具可以返回 ToolResult 格式的 dict 或任意值 |
| 统计 | `self._stats.record(...)` | 仅在 stats 存在时记录，不影响无统计场景的性能 |

### 2.3 装饰器注册模式

```python
def tool(self, name, description="", parameters=None):
    """装饰器：@registry.tool("name")"""
    def decorator(func):
        schema = ToolSchema(name=name, description=..., parameters=...)
        self.register(name, func, schema)   # 注册到 _tools 和 _schemas
        return func                        # 返回原函数不变
    return decorator
```

使用示例：

```python
registry = ToolRegistry()

@registry.tool("greet", description="打招呼", parameters=[
    ToolParam("name", ToolParamType.STRING, "名字")
])
def greet(name: str) -> dict:
    return {"success": True, "result": f"Hello, {name}!"}
```

**装饰器的执行时机是定义时（import 时），不是调用时。** 这意味着只要 Python 加载了这段代码，工具就已经注册好了——不需要额外初始化步骤。

### 2.4 _register_defaults() — 启动即就绪

```python
def _register_defaults(self) -> None:
    default_tools.register_default_tools(self)
```

委托给外部模块 `default_tools.py`，实现了**注册逻辑与注册内容分离**：
- `tool_registry.py` 管"怎么注册"
- `default_tools.py` 管"注册什么"

## 3. default_tools.py — 八个工具的具体实现

### 3.1 安全常量区

```python
DANGEROUS_KEYWORDS = [
    "rm -rf", "rm -r", "rmdir", "mkfs", "dd ",
    "format", "shutdown", "reboot", "halt", "poweroff",
    "> /dev/", "chmod 777", "useradd", "userdel",
]

PROTECTED_PATHS = ["/etc", "/usr", "/root", "/boot", "/bin", "/sbin", "/lib"]
```

**DANGEROUS_KEYWORDS 设计要点：**
- 用的是子串匹配（`if kw in cmd_lower`），不是精确匹配
- 所以 `rm -rf /` 会匹配到 `rm -rf`；`sudo rm -rf` 也会匹配
- 但 `echo "don't use rm -rf"` 这种不会误报（因为包含空格等上下文）

**PROTECTED_PATHS 设计要点：**
- 使用路径前缀匹配：`resolved.startswith(pp)`
- `/etc/passwd` 会命中 `/etc`；`/etcfoo` 也会（但这是极端边界情况）
- `Path.resolve()` 先解析符号链接和相对路径再检查

### 3.2 copy_file — 复制文件（最常用的工具之一）

```python
def copy_file(src: str, dest: str) -> dict:
    src_path = Path(src).expanduser().resolve()    # ~/Downloads → C:\Users\xxx\Downloads
    dest_path = Path(dest).expanduser()

    if not src_path.exists():                       # 前置校验
        return ToolResult.fail(f"源文件不存在: {src_path}").to_dict()

    if dest_path.is_dir():                         # 目标是目录？→ 自动拼接文件名
        dest_path = dest_path / src_path.name       # copy_file("a.txt", "./dir/") → ./dir/a.txt

    dest_path.parent.mkdir(parents=True, exist_ok=True)  # 自动创建父目录
    if src_path.is_dir():
        shutil.copytree(src_path, dest_path, dirs_exist_ok=True)  # 目录递归复制
    else:
        shutil.copy2(src_path, dest_path)                    # 单文件+保留元数据

    return ToolResult.ok(f"已复制: {src_path} → {dest_path}").to_dict()
```

**关键技术点：**
- `expanduser()` — 把 `~` 展开为用户主目录（跨平台：Windows 是 `C:\Users\...`，Linux 是 `/home/...`）
- `resolve()` — 变为绝对路径，消除 `.` 和 `..`
- `copy2()` vs `copy()` — copy2 保留修改时间、权限等元数据
- `dirs_exist_ok=True` — Python 3.8+ 参数，允许目标目录已存在

### 3.3 run_command — 最危险也最强大的工具

```python
def run_command(cmd: str, timeout: int = 30) -> dict:
    danger = _is_dangerous_command(cmd)           # 第一道安检
    if danger:
        return ToolResult.fail(f"拒绝执行: {danger}").to_dict()

    try:
        result = subprocess.run(                   # 第二道防线：subprocess 自身安全
            cmd, shell=True,
            capture_output=True, text=True,        # 捕获 stdout/stderr
            timeout=timeout,                       # 第三道防线：超时保护
        )
        output = result.stdout.strip()
        if result.returncode != 0:                 # 检查退出码
            error = result.stderr.strip()
            return ToolResult.fail(f"命令失败 (code={result.returncode}): {error}").to_dict()
        return ToolResult.ok(output or "(无输出)").to_dict()

    except subprocess.TimeoutExpired:
        return ToolResult.fail("命令执行超时").to_dict()
```

**三重防护：**
1. 黑名单关键词检查（我们自定义的）
2. `subprocess.run()` 本身不会继承父进程的所有环境变量风险
3. 30 秒超时防止命令挂死

**shell=True 的选择：** 使用 shell 模式是为了支持管道、通配符等 shell 特性（如 `ls *.py | wc -l`）。代价是安全性略低——但黑名单弥补了这一点。

## 4. skill_library.py — 高阶技能编排

### 4.1 FILE_CATEGORIES — 文件分类引擎

```python
FILE_CATEGORIES: dict[str, list[str]] = {
    "文档": [".pdf", ".doc", ".docx", ".xls", ".xlsx", ...],
    "图片": [".jpg", ".jpeg", ".png", ".gif", ...],
    ...
}
```

这是一个 **O(C × E)** 的查找表，C=7 个分类，E≈40 个扩展名。查找复杂度 O(C × E)，但因为 C 和 E 都很小，实际就是几十次字符串比较，微秒级。

**_classify() 方法：**

```python
def _classify(self, ext: str) -> str:
    for category, exts in self.FILE_CATEGORIES.items():
        if ext in exts:
            return category
    return "其他"
```

线性扫描，找到第一个匹配就返回。如果未来分类增多，可以用字典反转优化为 O(1)：

```python
# 优化版本（当前未采用，因为规模不够大）
_EXT_MAP = {}  # ".pdf" → "文档"
for cat, exts in FILE_CATEGORIES.items():
    for e in exts:
        _EXT_MAP[e] = cat
```

### 4.2 organize_downloads — 核心演示功能

完整算法流程图：

```
输入: path = "~/Downloads"
  │
  ├─ ① base = Path("~/Downloads").expanduser().resolve()
  │     → /home/user/Downloads （或 Windows: C:\Users\xxx\Downloads）
  │
  ├─ ② base.is_dir() 检查
  │     → False → 返回 error
  │
  ├─ ③ for f in base.iterdir():
  │     │
  │     ├─ f.is_file()?  → 不是则跳过（目录不动）
  │     │
  │     ├─ f.name.startswith(".")?  → 隐藏文件跳过
  │     │
  │     ├─ category = _classify(f.suffix.lower())
  │     │     → ".PDF" → ".pdf" → "文档"
  │     │
  │     ├─ dest_dir = base / category
  │     │     → /home/user/Downloads/文档/
  │     │
  │     ├─ dest_dir.mkdir(exist_ok=True)
  │     │     → 已存在也不报错
  │     │
  │     ├─ dest = dest_dir / f.name
  │     │
  │     ├─ dest.exists()?  → 重命名为 xxx_dup.ext
  │     │
  │     └─ shutil.move(str(f), str(dest))  ← 真正的文件移动
  │
  └─ ④ 返回汇总结果
```

**边界情况处理：**
- 目标目录已有同名文件 → `_dup` 后缀避免覆盖
- 隐藏文件（`.gitignore`, `.DS_Store`）→ 不动，归入 skipped 列表
- 空目录 → total_moved = 0，正常返回
- 符号链接 → `is_file()` 对链接指向的目标判断，move 会移动链接本身

### 4.3 find_duplicate_files — MD5 哈希去重

```python
hashes: dict[str, list[str]] = {}

for item in target.rglob("*"):
    if not item.is_file():
        continue
    with open(item, "rb") as f:
        h = hashlib.md5(f.read()).hexdigest()   # 读全部内容算 MD5
    hashes.setdefault(h, []).append(str(item))

duplicates = {h: paths for h, paths in hashes.items() if len(paths) > 1}
```

**为什么用 MD5 不用 SHA256？**
- 对于"找重复文件"这个场景，MD5 的碰撞概率已经足够低（2^64 分之一）
- MD5 计算速度更快（对大目录扫描很重要）
- 如果需要密码学安全级别，才需要升级 SHA256

**内存考虑：** 每个文件的哈希值只有 32 字符（MD5 hex），1000 个文件只需约 64KB 内存存哈希表。

## 5. mcp_connector.py — 协议桥梁

### 5.1 Server 管理（内存字典）

```python
def connect_server(self, name, config) -> dict:
    if name in self.servers:
        return {"success": False, "error": f"服务器 '{name}' 已连接"}
    self.servers[name] = {
        "name": name,
        "config": config,
        "status": "connected",
        "tools_count": 0,
    }
    return {"success": True, "server_id": name}
```

**幂等性保证：** 同名 server 不能重复连接，必须先 disconnect。

**真实 MCP 场景对应：** 未来替换为启动子进程（`subprocess.Popen`）连接真实的 MCP Server，config 里会传 `command` 和 `args`（如 `npx -y @modelcontextprotocol/server-xxx`）。

### 5.2 mock_jsonrpc_call — JSON-RPC 封装器

```python
def mock_jsonrpc_call(self, registry, name, params) -> dict:
    req_id = abs(hash(datetime.now().isoformat())) % 100000  # 简单 ID 生成
    result = registry.call(name, params)                      # 调用真实/Mock 工具
    return {
        "jsonrpc": "2.0",
        "result": result.result if result.success else None,
        "error": None if result.success else {"code": -32603, "message": result.error},
        "id": req_id,
    }
```

**ID 生成方式：** 用当前时间的 hash 截断到 5 位数字。这不是生产级 UUID，但对 Mock 来说足够唯一。真实 MCP 实现应改为客户端生成请求 ID 并传入。

**error code -32603：** 这是 JSON-RPC 2.0 规范中预定义的 "Internal error" 码，表示服务端内部出错（对应我们的"工具未注册"或"执行异常"）。

## 6. stats.py — 调用统计与审计

### 6.1 数据模型

```python
_records: list[dict]      # 原始记录列表（追加写入）
_counters: dict            # 聚合计数器（按工具名）
                         # {"copy_file": {"calls":5, "success":4, "fail":1}}
```

两种存储互补：
- `_records` — 保留每次调用的详细信息（时间、参数、耗时），适合调试
- `_ counters` — 聚合后的统计摘要，适合快速查看健康状态

### 6.2 record() — 每次调用都触发

```python
def record(self, record: CallRecord) -> None:
    entry = {
        "time": datetime.now().isoformat(),     # ISO 8601 时间戳
        "tool": record.tool_name,
        "params": record.params,                 # 记录了什么参数
        "success": record.success,
        "duration_ms": round(record.duration_ms, 2),
    }
    if record.error:
        entry["error"] = record.error

    self._records.append(entry)                  # 追加到列表

    c = self._counters.setdefault(record.tool_name, {"calls":0, "success":0, "fail":0})
    c["calls"] += 1
    c["success"] += 1 if record.success else 0
    c["fail"] += 0 if record.success else 1

    if self._log_path:
        self._save()                              # 有路径就持久化
```

**性能注意：** 每次 record 都可能触发磁盘写入（如果设置了 log_path）。高频场景下可以考虑批量写入或异步刷盘。但对于课程项目的频率完全没问题。

### 6.3 原子写入 — 防崩溃损坏

```python
def _save(self) -> None:
    data = {...}                                  # 组装完整数据
    with tempfile.NamedTemporaryFile(...) as f:   # 写临时文件
        json.dump(data, f, indent=2, ensure_ascii=False)
        tmp_path = f.name
    os.replace(tmp_path, self._log_path)          # 原子替换
```

**为什么不用直接 open 写？**
- 直接写如果在写到一半时程序崩溃 → 文件损坏（一半新数据一半旧数据）
- 先写临时文件 → `os.replace()` 是原子操作（要么成功要么失败，不会有中间状态）

这是数据库领域经典的 **WAL (Write-Ahead Log)** 思想的简化版。

## 7. 设计模式总结

本项目中使用的核心设计模式：

| 模式 | 应用位置 | 解决的问题 |
|------|---------|-----------|
| **策略模式** | ToolRegistry._tools 字典 | 不同工具用不同函数处理，运行时选择 |
