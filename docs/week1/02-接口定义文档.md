# 接口定义文档

## 一、为什么先定义接口

五个分组并行开发，各组代码最终要拼到一起运行。如果各自随意定义函数签名和返回格式，集成时会变成灾难。接口定义就是在代码一行没写之前，先把"合同"签好——所有组都按这份合同对接，各自独立开发互不冲突。

对分组四而言，接口定义解决两个核心问题：

- **对接组3（AppAgent）**：组3的 Automator 在执行 GUI 操作时，需要调用分组四的工具完成文件操作、命令执行等底层任务。接口明确了组3该传什么参数、能拿到什么返回值。
- **自身模块内聚**：`ToolRegistry`、`SkillLibrary`、`ToolStats` 三个组件通过接口耦合，不依赖具体实现，后续可以随意替换（Mock 或 真实实现）。

## 二、统一返回格式：`ToolResult`

任务书明确规定分组四的输出格式为 `tool_result_json`：`{"success": true, "result": "..."}`。所有组件的对外返回值都必须遵守这一格式。

```python
@dataclass
class ToolResult:
    """工具调用的统一返回格式。Group 3 AppAgent 调用后收到的就是此结构。"""
    success: bool              # 调用是否成功
    result: Any = None         # 成功时的返回数据，可以是任意类型
    error: str | None = None   # 失败时的错误描述

    # 便捷构造方法
    @staticmethod
    def ok(result: Any = None) -> "ToolResult":
        """成功：ToolResult.ok("复制完成")"""
        return ToolResult(success=True, result=result)

    @staticmethod
    def fail(error: str) -> "ToolResult":
        """失败：ToolResult.fail("源文件不存在")"""
        return ToolResult(success=False, error=error)

    def to_dict(self) -> dict:
        """转为 JSON 友好的字典，对接任务书 tool_result_json 格式"""
        if self.success:
            return {"success": True, "result": self.result}
        return {"success": False, "error": self.error}
```

**设计要点：**

- `success` 字段让调用方（组3）能用 `if result.success` 直接判断，不依赖异常处理
- 成功和失败走不同的字段（`result` vs `error`），杜绝歧义
- `to_dict()` 保证输出格式与任务书要求完全一致
- `ok()` 和 `fail()` 是两个静态工厂方法，让构造代码更语义化

## 三、工具描述结构：`ToolSchema`

MCP 协议要求每个工具附带一份"说明书"（schema），描述工具名称、功能、参数。分组四采用同样的设计：

### 3.1 ToolSchema

```python
@dataclass
class ToolSchema:
    """工具的完整描述——给 AppAgent 的 LLM 看的"菜单"。"""
    name: str                              # 工具唯一标识，如 "copy_file"
    description: str                       # 人类可读的功能描述
    parameters: list[ToolParam] = []       # 参数列表
    permission: PermissionLevel = USER     # 权限级别（public/user/admin）

    def to_dict(self) -> dict:
        """转为 MCP 风格的 inputSchema 格式"""
        return {
            "name": self.name,
            "description": self.description,
            "permission": self.permission.value,
            "inputSchema": {
                "type": "object",
                "properties": {...},   # 每个参数的类型和描述
                "required": [...]      # 必填参数列表
            }
        }
```

### 3.2 ToolParam

```python
@dataclass
class ToolParam:
    """单个参数的描述——类型、说明、是否必填、默认值。"""
    name: str
    type: ToolParamType             # string | number | boolean | object | array
    description: str = ""
    required: bool = True
    default: Any = None
```

### 3.3 ToolParamType

```python
class ToolParamType(str, Enum):
    STRING  = "string"
    NUMBER  = "number"
    BOOLEAN = "boolean"
    OBJECT  = "object"
    ARRAY   = "array"
```

**设计要点：**

- `ToolSchema` 为每个工具建立"自描述"——哪怕没看过代码的人，通过 `list_tools()` 就能知道有哪些工具、怎么调用
- `ToolParamType` 覆盖五种基本 JSON 类型，与 MCP 协议对齐
- `permission` 字段映射三级权限模型
- `to_dict()` 直接输出 JSON 友好的字典格式，支持 MCP 协议对接

## 四、抽象接口契约

三个核心抽象类确保 Mock 和真实实现可以无缝切换：

### 4.1 `IToolRegistry` — 工具注册表接口

```python
class IToolRegistry(ABC):
    """工具注册表接口。组3 AppAgent 通过此接口调用工具。"""

    @abstractmethod
    def register(self, name: str, func: ToolFunc,
                 schema: ToolSchema | None = None) -> None:
        """注册一个工具。传入名称、函数和可选的 schema。"""
        ...

    @abstractmethod
    def unregister(self, name: str) -> bool:
        """注销一个工具。返回是否成功。"""
        ...

    @abstractmethod
    def call(self, name: str, params: dict | None = None,
             user_level: PermissionLevel = USER) -> ToolResult:
        """调用一个工具。这是组3日常使用最多的入口。"""
        ...

    @abstractmethod
    def list_tools(self) -> list[ToolSchema]:
        """列出所有已注册工具——供 LLM 做工具选择。"""
        ...

    @abstractmethod
    def has(self, name: str) -> bool:
        """检查某工具是否已注册。"""
        ...
```

**组3如何使用这个接口：**

```python
# 组3 AppAgent 调用工具的代码
registry = ToolRegistry()  # 或者 MockToolRegistry()

# 方式1：直接调用工具
result = registry.call("copy_file", {"src": "/a.txt", "dest": "/b.txt"})
print(result.to_dict())  # {"success": True, "result": "已复制: a.txt → b.txt"}

# 方式2：查看有哪些工具可用
tools = registry.list_tools()
for t in tools:
    print(f"{t.name}: {t.description}")

# 方式3：检查工具是否存在再调用
if registry.has("organize_downloads"):
    result = registry.call("organize_downloads", {"path": "~/Downloads"})
```

### 4.2 `ISkillLibrary` — OS 技能库接口

```python
class ISkillLibrary(ABC):
    """OS Skills 库接口。Skill = 多个 Tool 的编排组合。"""

    @abstractmethod
    def register_skill(self, name: str, func: ToolFunc,
                       schema: ToolSchema | None = None) -> None:
        """注册一个 Skill。"""
        ...

    @abstractmethod
    def call_skill(self, name: str,
                   params: dict | None = None) -> ToolResult:
        """调用一个 Skill。如 organize_downloads。"""
        ...

    @abstractmethod
    def list_skills(self) -> list[ToolSchema]:
        """列出所有已注册的 Skill。"""
        ...
```

**Skill 与 Tool 的关系示例：**

以 `organize_downloads` 为例——这是一个 Skill，内部编排了多个 Tool：

```
organize_downloads (Skill 层)
  │
  ├── list_directory(path)         → 扫描目录下所有文件
  │     返回 [{name: "a.pdf", type: "file", ...}, ...]
  │
  ├── 按扩展名分类 (.pdf→文档, .jpg→图片, .mp3→音频, ...)
  │
  ├── create_folder("文档")        → 创建分类子目录
  ├── create_folder("图片")
  ├── create_folder("音频")
  │
  └── move_file(src, dest) × N    → 逐个搬运文件
       返回 {"success": true, "result": ...}
```

组3只需调用一个 `call_skill("organize_downloads")`，完全不需要关心内部编排。这就是 Skill 层抽象的价值。

### 4.3 `IToolStats` — 调用统计接口

```python
class IToolStats(ABC):
    """工具调用统计——记录每次调用用于调试和审计。"""

    @abstractmethod
    def record(self, record: CallRecord) -> None:
        """记录一次调用。"""
        ...

    @abstractmethod
    def report(self) -> dict[str, dict[str, int]]:
        """统计报告：{tool_name: {calls, success, fail}}。"""
        ...

    @abstractmethod
    def total_calls(self) -> int:
        """总调用次数。"""
        ...
```

### 4.4 `CallRecord` — 单次调用记录

```python
@dataclass
class CallRecord:
    """一次工具调用的记录。"""
    tool_name: str
    params: dict[str, Any]
    success: bool
    duration_ms: float       # 毫秒
    error: str | None = None
```

**统计数据示例：**

```json
{
  "copy_file":  {"calls": 12, "success": 12, "fail": 0},
  "move_file":  {"calls": 4,  "success": 4,  "fail": 0},
  "run_command": {"calls": 3,  "success": 2,  "fail": 1}
}
```

### 4.5 `PermissionLevel` — 权限级别

```python
class PermissionLevel(str, Enum):
    PUBLIC = "public"          # 人人可调：list_directory, read_file
    USER   = "user"            # 普通用户：copy_file, move_file, delete_file
    ADMIN  = "admin"           # 仅管理员：run_command（危险命令）

    def rank(self) -> int:
        """用于权限比较：public=0 < user=1 < admin=2"""
        return {"public": 0, "user": 1, "admin": 2}[self.value]
```

权限验证逻辑：

```python
# ToolRegistry.call() 中的权限检查
schema = self._schemas.get(name)
required_perm = schema.permission if schema else PermissionLevel.USER
if user_level.rank() < required_perm.rank():
    return ToolResult.fail(
        f"权限不足: '{name}' 需要 {required_perm.value}, "
        f"当前为 {user_level.value}"
    )
```

## 五、接口数据流示意

```
组3 AppAgent
    │
    │  registry.call("copy_file", {"src": ..., "dest": ...})
    ▼
──────────────────── 接口边界（IToolRegistry）────────────────────
    │
    ▼
ToolRegistry (真实实现)
    │
    ├── 权限校验：user_level.rank() >= required_perm.rank()
    │
    ├── 参数校验：TypeError catch
    │
    ├── 执行工具：shutil.copy2(src, dest)
    │
    ├── 统计记录：stats.record(CallRecord(...))
    │
    └── 返回结果：ToolResult.ok("已复制: a.txt → b.txt")
    │
    ▼
──────────────────── 接口边界（ToolResult）────────────────────
    │
    ▼
ToolResult.to_dict() → {"success": true, "result": "已复制: a.txt → b.txt"}
    │
    ▼
组3 AppAgent 接收结果，继续执行下一步
```

### Mock 模式下的数据流

```
组3 AppAgent（开发期）
    │
    │  mock_registry.call("copy_file", {"src": ..., "dest": ...})
    ▼
──────────────────── 接口边界（IToolRegistry）────────────────────
    │
    ▼
MockToolRegistry (不执行真实文件操作)
    │
    └── 直接返回：ToolResult.ok("[Mock] copy_file 执行成功（模拟）")
    │
    ▼
ToolResult.to_dict() → {"success": true, "result": "[Mock] copy_file 执行成功"}
    │
    ▼
组3 拿到模拟结果，继续开发 AppAgent 逻辑
```

注意：真实实现和 Mock 实现共享同一个 `IToolRegistry` 接口——切换只需要改一行 import。

## 六、接口文件结构

```
src/interfaces.py
│
├── 类型枚举
│   ├── ToolParamType     # string | number | boolean | object | array
│   └── PermissionLevel   # public | user | admin
│
├── 数据类
│   ├── ToolParam         # 参数名、类型、描述、是否必填、默认值
│   ├── ToolSchema        # name + description + parameters + permission
│   └── ToolResult        # success + result + error
│
├── 统计相关
│   ├── CallRecord        # 单次调用记录：tool_name, params, success, duration_ms
│   └── IToolStats        # record() + report() + total_calls()
│
├── 核心接口
│   ├── IToolRegistry     # register + unregister + call + list_tools + has
│   └── ISkillLibrary     # register_skill + call_skill + list_skills
│
└── 类型别名
    └── ToolFunc          # Callable[..., dict[str, Any]]
```

## 七、接口使用示例

```python
from src import ToolRegistry, SkillLibrary, ToolStats, PermissionLevel

# 初始化
stats = ToolStats("stats.json")
registry = ToolRegistry(stats=stats)
skills = SkillLibrary(registry=registry)

# 基本工具调用
r = registry.call("copy_file", {"src": "/home/user/a.txt", "dest": "/tmp/a.txt"})
print(r.to_dict())  # {"success": True, "result": "已复制 a.txt → b.txt"}

# 权限验证：public 只能调用只读工具
r = registry.call("run_command", {"cmd": "ls"}, PermissionLevel.PUBLIC)
print(r.to_dict())  # {"success": False, "error": "权限不足..."}

# OS Skill 调用
r = skills.call_skill("organize_downloads", {"path": "~/Downloads"})
print(r.to_dict())  # {"success": True, "result": {"total_moved": 15, "categories": {...}}}

# 动态注册新工具
def my_custom_tool(msg: str) -> dict:
    return {"success": True, "result": f"ECHO: {msg}"}

registry.register("echo", my_custom_tool)
r = registry.call("echo", {"msg": "hello"})
print(r.to_dict())  # {"success": True, "result": "ECHO: hello"}

# 查看统计
stats = registry._stats.report()
print(stats)  # {"copy_file": {"calls": 1, "success": 1, "fail": 0}, ...}
```
