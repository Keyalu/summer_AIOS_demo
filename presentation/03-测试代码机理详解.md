## 核心原理：三层调用模型

在深入每个案例前，先理解通用的调用结构：

```
┌─────────────────┐     ┌──────────────────┐     ┌──────────────────┐
│   测试代码层      │ →   │  ToolRegistry层   │ →   │  具体工具函数层    │
│  (test_all.py)   │     │(tool_registry.py) │     │(default_tools.py)│
│                  │     │                  │     │                  │
│ 调用 + 断言       │     │ 权限检查+调度      │     │ 真实的OS操作       │
│ "我要复制文件"    │     │ "有权限吗？"       │     │ shutil.copy2()   │
│ "成功了吗？"     │     │ "调用哪个函数？"   │     │ subprocess.run() │
└─────────────────┘     └──────────────────┘     └──────────────────┘
```

**每一层的职责**：
- **测试代码**：发起动作 + 验证结果（"我要求X，确认得到了Y"）
- **ToolRegistry**：中间人（检查权限、找到对应函数、包装返回值）
- **具体工具函数**：真正干活的人（执行OS操作）

## 案例1：验证工具是否注册

### 测试代码

```python
def test_default_tools_registered(self):
    """验证：构造 ToolRegistry 后，8个默认工具应该已经注册好了"""
    assert self.registry.has("copy_file")      # 断言1：copy_file 存在
    assert self.registry.has("move_file")      # 断言2：move_file 存在
    assert self.registry.has("run_command")    # 断言3：run_command 存在
    # ... 共8个断言
```

### 调用链追踪

```
self.registry.has("copy_file")
│
└── tool_registry.py:130-131 的 has() 方法：
    │
    def has(self, name: str) -> bool:
        return name in self._tools    # ← 检查 _tools 字典中有没有这个key
        │
        ├── self._tools 是什么？
        │   └── 它是一个字典 dict[str, ToolFunc]
        │
        ├── 什么时候被填充的？
        │   └── __init__() 中调用了 _register_defaults()
        │       └── default_tools.py:259-273 的 register_default_tools()
        │           ├── registry.register("copy_file", copy_file, schema)
        │           ├── registry.register("move_file", move_file, schema)
        │           └── ... 注册全部8个工具
        │
        └── 所以 name in self._tools 实际上是在问：
            "copy_file" 这个字符串是不是 _tools 字典的一个 key？

            _tools = {
                "copy_file": <function copy_file>,    ← 有！
                "move_file": <function move_file>,
                ...
            }

            → 返回 True ✅
```

### 为什么能证明功能？

| 断言 | 验证了什么 | 为什么重要 |
|------|-----------|-----------|
| `has("copy_file")` == True | `register()` 函数正确执行了 | 如果注册失败，后续 `call()` 会报"工具未注册" |
| 8个工具都有 | `_register_defaults()` 没遗漏 | 说明初始化逻辑完整 |

**通俗比喻**：
这就像检查餐厅开门后，厨师们是否都已经到位。
- `has("copy_file")` = 问"负责切菜的厨师来了吗？"
- 如果返回True = 切菜师傅已就位，客人点了"拍黄瓜"就能做出来。

## 案例2：验证文件复制功能

### 测试代码

```python
def test_copy_file(self):
    with tempfile.TemporaryDirectory() as tmp:
        src = os.path.join(tmp, "src.txt")
        dest = os.path.join(tmp, "dest.txt")

        with open(src, "w") as f:          # Step A：手动创建源文件
            f.write("original")

        r = self.registry.call(             # Step B：通过Registry调用复制
            "copy_file",
            {"src": src, "dest": dest}
        )

        assert r.success is True            # 断言1：操作成功
        assert os.path.exists(dest)         # 断言2：目标文件存在
        with open(dest) as f:               # 断言3：内容一致
            assert f.read() == "original"
```

```

│

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【Step B】r = self.registry.call("copy_file", {"src": src, "dest": dest})
│
└── 进入 tool_registry.py:62-125 的 call() 方法
    │
    ├── 【第1步】参数处理 (line 76)
    │   params = {"src": ".../src.txt", "dest": ".../dest.txt"}
    │
    ├── 【第2步】工具存在性检查 (line 78-79)

    │
    ├── 【第3步】权限检查 (line 82-87)

    │   user_level = PermissionLevel.USER     # 默认传入值
    │   │
    │   if user_level.rank() < required_perm.rank():
    │       return ToolResult.fail("权限不足...")
    │   │
    │   ├── USER.rank() = 1
    │   ├── USER.rank() >= USER.rank()? → 1 >= 1 → True → 通过 ✓
    │   └── 不需要ADMIN权限，USER就够用了
    │
    ├── 【第4步】真正调用工具函数 (line 91)
    │   raw = self._tools["copy_file"](src=".../src.txt", dest=".../dest.txt")
    │   │
    │   └── 这相当于直接调用 default_tools.py 的 copy_file() 函数：
    │       │
    │       def copy_file(src: str, dest: str) -> dict:
    │           src_path = Path(src).expanduser().resolve()   # 解析为绝对路径
    │           dest_path = Path(dest).expanduser()          # 展开用户目录(~)
    │
    │           if not src_path.exists():                     # 检查源文件是否存在
    │               return ToolResult.fail("源文件不存在").to_dict()
    │           │   └── 我们在Step A已经创建了 → exists() = True → 继续 ✓
    │
    │           dest_path.parent.mkdir(parents=True, exist_ok=True)  # 创建父目录
    │           shutil.copy2(str(src_path), str(dest_path))           # ⭐ 真正的复制操作！
    │           │
    │           └── shutil.copy2() 做了什么？
    │               ├── 读取 src.txt 的所有字节
    │               ├── 写入到 dest.txt
    │               └── 复制元数据（修改时间、权限等）
    │
    │           return ToolResult.ok(f"已复制: {src} → {dest}").to_dict()
    │           │   └── 返回 {"success": True, "result": "已复制: ..."}
    │
    ├── 【第5步】包装返回值 (line 94-97)
    │   isinstance(raw, dict)? → True (因为 .to_dict() 返回dict)
    │   raw["success"] is True?
    │   └── → result = ToolResult(success=True, result="已复制: ...")
    │
    ├── 【第6步】记录统计 (line 99-104)
    │   if self._stats:  → 这里没传stats → 跳过
    │
    └── 【返回】result = ToolResult(success=True, result="已复制: ...")

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【断言1】assert r.success is True
│
└── r.success 是从哪来的？
    └── ToolResult.ok() 设置 success=True → call() 包装后保持不变
    │
    └── 为什么 success=True 就证明复制成功了？
        因为 copy_file() 只有在 shutil.copy2() 成功执行后才返回 ok()
        如果中途出错（文件不存在、权限不足等），会返回 fail()

【断言2】assert os.path.exists(dest)
│
└── 直接检查操作系统：dest.txt 这个文件是否存在？
    │
    └── shutil.copy2() 确实把文件写入到了磁盘上 → 文件真的存在 ✓

【断言3】assert f.read() == "original"
│
└── 打开 dest.txt 读取内容，确认和源文件完全一致
    │
    └── 不仅文件存在，内容也完全相同 → 复制完整无误 ✓
```

### 为什么能证明功能？

| 断言 | 验证了什么 | 失败意味着什么 |
|------|-----------|--------------|
| `r.success == True` | 整个调用链没有异常 | 可能：权限不足、源文件不存在、shutil报错 |
| `os.path.exists(dest)` | 文件真的被创建了 | 可能：路径错误、磁盘满、权限问题 |
| `f.read() == "original"` | 内容完全一致 | 可能：编码错误、复制中断、文件损坏 |

**三重验证形成闭环**：
```
逻辑层验证（success=True）
    ↓
物理层验证（文件存在）
    ↓
数据层验证（内容一致）
    ↓
✅ 复制功能100%正确实现
```

## 案例3：验证权限控制

### 测试代码

```python
def test_permission_admin_required(self):
    # USER 尝试调用 run_command → 应该失败
    r1 = self.registry.call(
        "run_command",
        {"cmd": "echo hi"},
        PermissionLevel.USER
    )
    assert r1.success is False                    # 断言1：失败
    assert "权限不足" in r1.error                 # 错误信息包含"权限不足"

    # ADMIN 调用同样的命令 → 应该成功
    r2 = self.registry.call(
        "run_command",
        {"cmd": "echo hello"},
        PermissionLevel.ADMIN
    )
    assert r2.success is True                     # 断言3：成功
    assert "hello" in r2.result                   # 输出包含 "hello"
```

```
    ├── 权限检查 (line 82-87):

    │   schema = TOOL_SCHEMAS["run_command"]
```

### 为什么两个调用对比才能证明权限系统？

单独一个断言不够：

```python
# ❌ 只测失败情况
assert fail_result.success == False
# 可能是因为"工具未注册"，而不是"权限不足"

# ❌ 只测成功情况  
assert success_result.success == True
# 可能根本没做权限检查，只是恰好成功了

# ✅ 对比测试（我们实际的做法）
# 同样的命令、不同的权限级别 → 结果不同
USER  → 失败（"权限不足"）
ADMIN → 成功（输出"hello"）
# 结论：权限系统确实在工作！
```

**这就是"对照实验"的思想——控制变量法**

## 案例4：验证安全机制（危险命令拦截）

### 测试代码

```python
def test_dangerous_command_blocked(self):
    r = self.registry.call(
        "run_command",
        {"cmd": "rm -rf /"},              # 危险命令！
        PermissionLevel.ADMIN              # 甚至给了最高权限
    )
    assert r.success is False              # 应该被拦截
    assert "拒绝执行" in r.error            # 错误信息要说明原因
```

### 调用链追踪

```
registry.call("run_command", {"cmd": "rm -rf /"}, ADMIN)
│
└── tool_registry.py call():
    │
    ├── 工具存在？→ ✓
    ├── 权限检查？→ ADMIN >= ADMIN → ✓ （权限通过了！）
    │
    ├── 执行函数 (line 91):
    │   raw = run_command(cmd="rm -rf /")
    │   │
    │   └── default_tools.py:166-187 run_command():
    │       │
    │       【关键！安全过滤在这里】
    │       danger = _is_dangerous_command("rm -rf /")
    │       │   │
    │       │   └── default_tools.py:41-46 _is_dangerous_command():
    │       │       │
    │       │       cmd_lower = "rm -rf /".lower().strip()  → "rm -rf /"
    │       │       │
    │       │       for kw in DANGEROUS_KEYWORDS:  # 遍历黑名单
    │       │           if kw in cmd_lower:
    │       │               return f"包含危险关键词: {kw}"
    │       │       │
    │       │       DANGEROUS_KEYWORDS = [
    │       │           "rm -rf", "rm -r", "rmdir", "mkfs", ...
    │       │       ]
    │       │       │
    │       │       "rm -rf" in "rm -rf /"? → True! 🚨
    │       │       └── return "包含危险关键词: rm -rf"
    │       │
    │       danger = "包含危险关键词: rm -rf"  (不是None！)
    │       │
    │       if danger:                              # line 169
    │           return ToolResult.fail(f"拒绝执行: {danger}").to_dict()
    │           │
    │           └── 返回 {"success": False,
    │                      "error": "拒绝执行: 包含危险关键词: rm -rf"}
    │
    └── 返回：ToolResult(success=False, error="拒绝执行: ...")

【断言1】assert r.success is False
│
└── 即使给了ADMIN权限，依然失败 → 安全机制优先级高于权限！

【断言2】assert "拒绝执行" in r.error
│
└── 明确知道是被安全机制拦截的，而不是其他原因（如命令语法错误）
```

### 为什么这个测试特别重要？

**它证明了安全机制的"硬性"**：

```
正常流程：权限检查 → 执行命令
                ↓
        如果权限够 → 执行

但这里：权限检查通过 → 执行命令 → 安全拦截
                                    ↓
                            即使是ADMIN也不行！

这就像：你是酒店老板（ADMIN），但你不能烧掉自己的酒店
→ 某些操作无论权限多高都被禁止
```

**如果没有这个测试会怎样？**
- 可能开发者删除了黑名单检查，但其他测试都通过了
- 生产环境中有人恶意注入 `rm -rf /`
- 整个系统被摧毁

所以这个测试是**安全底线**。

## 案例5：验证技能编排（多工具组合）

### 测试代码

```python
def test_organize_downloads(self):
    with tempfile.TemporaryDirectory() as tmp:
        # 准备测试数据：不同类型的文件
        Path(os.path.join(tmp, "a.pdf")).touch()   # PDF文件
        Path(os.path.join(tmp, "b.jpg")).touch()   # 图片文件
        Path(os.path.join(tmp, "c.mp3")).touch()   # 音频文件

        r = self.skills.call_skill("organize_downloads", {"path": tmp})

        assert r.success is True                        # 断言1：技能执行成功
        assert r.result["total_moved"] == 3             # 断言2：移动了3个文件
        assert os.path.isdir(os.path.join(tmp, "文档"))  # 断言3：创建了文档文件夹
        assert os.path.isdir(os.path.join(tmp, "图片"))  # 断言4：创建了图片文件夹
        assert os.path.isdir(os.path.join(tmp, "音频"))  # 断言5：创建了音频文件夹
```

### 调用链追踪（重点：Skill如何调用多个Tool）

```
skills.call_skill("organize_downloads", {"path": tmp})
│
└── skill_library.py 的 call_skill() 方法：
    │
    ├── 找到 organize_downloads 这个技能的定义
    │
    └── 执行技能逻辑（伪代码表示实际过程）：
        │
        total_moved = 0
        │
        【子步骤1】列出目录中的所有文件
        │   ├── 调用 registry.call("list_directory", {"path": tmp})
        │   │   └── 得到文件列表：[a.pdf, b.jpg, c.mp3]
        │
        【子步骤2】按扩展名分类
        │   ├── .pdf → 归类为"文档"
        │   ├── .jpg → 归类为"图片"
        │   └── .mp3 → 归类为"音频"
        │
        【子步骤3】创建文件夹（如果不存在）
        │   ├── registry.call("create_folder", {"path": tmp+"/文档"})
        │   ├── registry.call("create_folder", {"path": tmp+"/图片"})
        │   └── registry.call("create_folder", {"path": tmp+"/音频"})
        │   │   └── 每个 create_folder 调用都会触发：
        │       │   default_tools.create_folder()
        │       │   → Path(path).mkdir(parents=True, exist_ok=True)
        │       │   → 在文件系统中真实创建文件夹
        │
        【子步骤4】移动文件到对应文件夹
        │   ├── registry.call("move_file", {src: tmp+"/a.pdf", dest: tmp+"/文档/a.pdf"})
        │   │   └── shutil.move(a.pdf, 文档/a.pdf) → 文件移动成功！
        │   ├── registry.call("move_file", {src: tmp+"/b.jpg", dest: tmp+"/图片/b.jpg"})
        │   │   └── shutil.move(b.jpg, 图片/b.jpg) → 文件移动成功！
        │   └── registry.call("move_file", {src: tmp+"/c.mp3", dest: tmp+"/音频/c.mp3"})
        │       └── shutil.move(c.mp3, 音频/c.mp3) → 文件移动成功！
        │
        ├── total_moved += 1 (每次移动成功后计数)
        │
        └── 返回：{
            success: True,
            result: {
                total_moved: 3,
                categories: {"文档":1, "图片":1, "音频":1}
            }
        }
```

### 为什么能证明"技能编排"功能？

**关键点：这不是一个工具完成的，而是多个工具的组合**

```
organize_downloads 技能内部调用链：

list_directory (1次)     → 了解现状
    ↓
create_folder (3次)     → 准备环境
    ↓
move_file (3次)         → 执行移动
    ↓
汇总结果并返回
```

| 断言 | 证明了什么 |
|------|----------|
| `success == True` | 整个编排流程没有出错 |
| `total_moved == 3` | 3个文件都成功移动了（计数准确） |
| `"文档"` 目录存在 | create_folder 被正确调用 |
| `"图片"` 目录存在 | 分类逻辑识别了.jpg扩展名 |
| `"音频"` 目录存在 | 分类逻辑识别了.mp3扩展名 |

**如果只测试单个工具（如 move_file），无法发现的问题**：
- 技能内部的调用顺序错了？（先移动再创建文件夹？）
- 分类规则写错了？（.pdf被归到"图片"？）
- 计数逻辑错了？（移动了3个但显示2个？）

**所以技能层面的测试必不可少**——它验证的是"业务流程"的正确性。

## 案例6：验证统计功能

### 测试代码

```python
def test_stats_integration(self):
    stats = ToolStats()                          # 创建统计对象
    reg = ToolRegistry(stats=stats)               # 把stats传给Registry

    reg.call("list_directory", {"path": "."})     # 第1次调用

    assert stats.total_calls() == 2               # 断言1：总调用次数=2
    report = stats.report()
    assert report["list_directory"]["calls"] == 2  # 断言2：该工具被调用2次
    assert report["list_directory"]["success"] == 2 # 断言3：2次都成功
```

```
    │   │

    │       tool_name="list_directory",

【断言1】stats.total_calls() == 2
│

    return len(self._records)  → len([record1, record2]) = 2 ✓

【断言2】report()["list_directory"]["calls"] == 2
```

### 为什么能证明统计功能？

**统计功能的本质："每次调用都会留下痕迹"**

```
时间线：

t=0ms   创建 Registry + Stats
        ↓
t=10ms  第1次调用 list_directory
        │  ├─ 执行函数
        │  └─ stats.record()  ← 自动记录！
        ↓
t=25ms  第2次调用 list_directory
        │  ├─ 执行函数
        │  └─ stats.record()  ← 再次记录！
        ↓
t=30ms  断言检查
        ├─ 总调用数=2 ✓
        └─ 该工具调用数=2 ✓
```

**如果没有统计集成会怎样？**
- 无法知道哪些工具被频繁使用（性能优化依据）
- 无法计算成功率（质量监控）
- 出问题时没有日志可查（调试困难）

**这个测试证明了"自动记账"功能正常工作——每次消费（调用）都被记下来了。**

## 总结：测试证明能力的层次

### 测试覆盖的功能层次

```
层次1：基础功能（案例1、2）
├── 工具能否注册和调用？
├── 文件操作是否真的执行？
└── 证明：系统能"动起来"

层次2：安全与权限（案例3、4）
├── 权限控制是否生效？
├── 危险操作是否被拦截？
└── 证明：系统不会"乱来"

层次3：高级能力（案例5、6）
├── 多工具编排是否协调？
├── 统计记录是否准确？
└── 证明：系统具备"智能"

层次4：端到端集成（TestIntegration::test_full_data_flow）
├── 所有模块协同工作？
├── 数据流从头到尾通畅？
└── 证明：这是一个"完整产品"
```

### 为什么需要这么多测试？

```
单一测试的局限性：

test_copy_file 只证明：复制文件这一个功能
│
└── 不能保证：
    ├── 权限系统正常（可能任何人都能复制敏感文件）
    ├── 安全过滤正常（可能允许复制 /etc/passwd）
    ├── 编排正常（可能 organize_downloads 内部调用顺序错）
    └── 统计正常（可能调用次数记录不准确）

→ 所以需要不同维度的测试交叉验证
→ 形成"测试网"，任何bug都逃不掉
```

### 最终结论

**测试代码不是在"猜测"结果，而是在验证"因果关系"：**

```
输入（动作）
    ↓
预期行为（源码应该做什么）
    ↓
可观测的结果（返回值、文件状态、系统状态）
    ↓
断言（结果是否符合预期？）
    ↓
✅ 符合 → 功能正确实现
❌ 不符合 → 发现bug
```

每一个 `assert` 都是一张"证据照片"——证明源码确实按照预期工作了。
