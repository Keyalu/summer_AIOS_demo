# 05-输入输出演示流程详解

> 分组四 · Tools + OS Skills · 演示讲稿（配合根目录 `demo_io.py` 使用）
> 时长：约 3 分钟 | 形式：现场跑一条命令，屏幕滚动展示 5 个演示场景

---

## 一、这个演示回答什么问题

老师/组员最常问的一句话是：**"组3 调你们的工具，一次调用到底发生了什么？"**

本演示把一次调用的完整生命周期拆开给你看：

```
Agent 输入                        中间三道闸门                    统一输出
┌──────────────────┐   ┌─────────────────────────────┐   ┌──────────────────┐
│ tool: 工具名      │   │ ① 存在性检查（注册了吗）      │   │ success: true    │
│ params: 参数字典  │ ─▶│ ② 权限检查（够不够级别）      │ ─▶│   result: {...}  │
│ caller_level: 身份│   │ ③ schema 预检（参数齐不齐）   │   │ 或               │
└──────────────────┘   └─────────────────────────────┘   │ success: false   │
                              │ 全过才执行工具函数          │   error: "..."   │
                              │ 执行完记录统计              │ └──────────────────┘
```

**一句话总结（演示结尾也是这句）：**
输入是 `(工具名, 参数, 调用者身份)`，输出永远是 `{success, result/error}`，
中间三道闸门保证坏输入进不了工具函数。

## 二、怎么跑

```bash
# Windows（Anaconda 环境）
cd linux-agentic-os-group4
E:/anaconda3/python.exe demo_io.py

# WSL / Linux
cd linux-agentic-os-group4
/usr/bin/python3 demo_io.py
```

- 运行约 **10 秒**，无任何交互，适合投屏。
- 全程在**系统临时目录沙箱**内（`tempfile.mkdtemp`），不碰真实文件，讲的时候可以主动提这一点。

## 三、5 个演示场景逐个讲（约 3 分钟节奏）

| # | 场景 | 输入 | 结果 | 讲 30 秒的话术 |
|---|------|------|------|----------------|
| 1 | 正常调用 `list_directory` | path + limit=2 | ✅ 返回 2 条 + `has_more/next_offset` 分页信息 | "一路绿灯的路径：三道闸门全过，工具执行，统计记录。注意返回里带了分页游标——这是 Week3 高压优化的成果，上万个文件也只返回这一页。" |
| 2 | 权限拦截 `run_command` | cmd="rm -rf ..." | ❌ "权限不足： 需要 admin, 当前为 user" | "危险命令：工具要求 admin，普通调用者直接被拒。关键点是**拦截发生在执行之前**——shell 根本没启动，命令到不了系统。" |
| 3 | 参数预检 `write_file` | 只传 path 缺 content | ❌ "缺少必需参数: content" | "错误在进工具函数之前就被 schema 抓住了，Agent 拿到明确报错可以立刻自纠正，不用等执行失败。" |
| 4 | 技能调用 `system_check` | skill 编排层 | ✅ 磁盘/内存/进程数/主机名 | "Skill 是组合拳：一次输入，底层跑多个动作。注意 Windows 下 memory 显示不可用——数据源是 Linux 的 /proc，取不到就如实上报不假装成功，这就是跨平台降级设计。" |
| 5 | 统计报表 | （前 4 次调用的沉淀） | `report()`：每个工具的 calls/success/fail | "所有调用都被记下来了——包括失败的。Agent 可以据此自省：哪个工具失败率高就少用它。" |

## 四、现场可能被追问的 3 个问题（预备答法）

1. **"为什么失败的调用也要记统计？"**
   → 统计的意义恰恰在于暴露问题。演示 5 里 `write_file` 显示 fail:1，就是演示 3 故意制造的失败。Agent 做自省、我们做运维，都需要失败数据。

2. **"权限检查为什么放在 Registry 里而不是工具函数里？"**
   → 单一职责 + 不可绕过。工具函数只管干活，安全闸门集中在入口。如果让每个工具自己检查，8 个工具 8 套写法，漏一个就是漏洞。

3. **"演示 4 里技能为什么不经过 Registry？"**
   → Week3 与组3定死的契约：技能调用直接走 SkillLibrary，不产生重复统计。这样统计报表里的数字才是"真实工具调用次数"，不会被编排层虚增。详见《03-测试代码机理详解》里 test_integration 固化的两条契约。

## 五、如果想现场互动（可选 30 秒）

让台下同学随口说一个不存在的工具名，你当场加一段：

```python
registry.call("make_coffee")   # → {"success": false, "error": "工具未注册: make_coffee"}
```

顺便引出：这就是为什么组3在 Week1 就要我们的 Mock——接口行为从第一周就是定死的，今天看到的输出和 Mock 时代承诺的完全一致。
